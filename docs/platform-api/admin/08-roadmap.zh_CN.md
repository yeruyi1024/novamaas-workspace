# 插件更新、停用与排错

## 管理能力总表（供领导审核与研发对齐）

下表汇总当前代码实际实现的插件、连接器、Skill 与 MCP 管理边界。所有远程能力均通过星途客户端在线同步目录执行，不会越过客户端直接修改用户操作系统；客户端离线或未启动时不会即时生效。

| 能力类别与具体对象 | 来源属性（内置 vs 公司下发） | 能否远程更新（如何生效） | 能否远程停用 | 能否远程删除本机已装内容 | 是否需要用户确认 | 责任分工 |
|---|---|---|---|---|---|---|
| **内置连接器**：微信、钉钉、飞书、企业微信、邮件（共 5 项） | **客户端内置**（`management_type: "bundled"`，代码随星途安装包分发） | **能远程更新展示文案与排序**（名称、简介、`listed`/`visible`、`sort_order`）；**不能远程热更新连接器代码**，代码修改须随星途客户端发版并由用户升级安装包 | **仅能远程隐藏入口**（`listed: false` 或 `visible: false`）；**不能远程强制断开或停用已运行的连接器实例** | **不能**（无远程卸载或删除内置连接器文件的能力） | 后台修改展示无需用户确认；升级客户端安装包需用户执行升级 | Root 或连接器模块授权管理员管展示；客户端研发管连接器代码与发版 |
| **内置技能（Built-in Skill）** | **客户端内置**（随星途安装包内置资源目录提供） | **不能通过后台替换内置技能文件**；功能变更须由客户端研发修改内置资源并随新版本客户端发版 | **不能远程停用内置技能执行**（后台目录仅能控制是否作为公司推荐项展示） | **不能**（后台目录下架不会删除安装包内的内置技能文件） | 随客户端版本升级生效 | 客户端研发 |
| **内置 MCP 与宿主基础运行组件** | **客户端内置**（随星途安装包内置提供） | **不能远程热替换**；随星途客户端发版升级 | **不能**（不在公司 MCP `disabled_sources` 停用名单控制范围内） | **不能** | 随客户端版本升级生效 | 客户端研发 |
| **公司下发的技能包（Company Skill / `hosted_artifact` / `https_archive`）** | **公司后台下发**（由 MaaS 后台上传/导入 ZIP、确认固定版本并按全部或指定用户发布） | **能远程发布新版本推荐**；客户端同步后提示“可更新”，**不支持后台静默强制覆盖升级** | **仅能隐藏或下架推荐**（`listed: false` / 从目录移除）；**不能远程停用用户已安装到本地的技能** | **不能**（平台删除制品版本 `DELETE /releases/:id` 只清理服务端未引用对象，不触发客户端卸载本机副本） | **必须用户确认**：首次添加/安装与版本更新均需用户在星途界面主动点击确认 | Root 配对象存储；技能模块授权管理员上传确认并发布；星途用户确认安装与更新 |
| **公司下发的 MCP（Company MCP）** | **公司后台下发**（由 MaaS 后台配置传输方式、命令/地址、必填项声明并按用户发布） | **能远程发布新版本配置**；已安装用户看到“一键更新”提示，点击后保留本地密钥/环境变量并更新命令或地址 | **能远程统一停用**（后台设 `disabled: true` 发布后，客户端下次同步 `disabled_sources` 时**自动关闭**匹配的已装公司 MCP） | **不能**（统一停用仅将本机开关设为关闭，**不删除**用户已填配置或卸载记录） | **添加与更新需用户确认**（及填写必填密钥）；**平台统一停用无需用户确认，同步时自动强制关闭**（后续平台取消停用也不会自动重开，需用户手动开启） | MCP 模块授权管理员发布或停用；星途用户填写秘密配置并确认添加/更新 |
| **第三方市场安装的技能、MCP、插件** | **第三方市场来源**（非 `company:*` 来源） | 公司后台不接管；按市场与客户端原有机制由用户更新 | **不能通过公司后台停用** | **不能通过公司后台删除** | 由用户自行操作确认 | 星途用户与市场维护方 |
| **用户手动添加的本地技能、MCP、插件** | **用户自建来源** | 公司后台不接管、不覆盖用户自建项 | **不能通过公司后台停用** | **不能通过公司后台删除** | 由用户自行维护 | 星途用户 |

### 领导审核重点区分的四个管理动作

| 后台操作动作 | 实际生效行为 | 对用户电脑已安装内容的影响 | 是否需要用户确认 |
|---|---|---|---|
| **1. 隐藏或从目录移除（下架推荐）** | 目标用户的“公司推荐”列表不再展示该项，不再发送新增通知 | **不影响**用户此前已经安装到本机的技能、MCP 或已开启的连接器 | 后台隐藏立即在下次目录同步时生效，无需用户确认 |
| **2. 发布新版本（Skill 或 MCP）** | 平台提供新的固定版本技能包或新 MCP 传输参数，客户端对比本地版本后展示“可更新” | **不会静默覆盖**用户正在使用的版本；用户未点击更新前继续运行旧版本 | **必须用户点击确认**后才执行下载替换或配置更新 |
| **3. 统一停用公司 MCP（`disabled: true`）** | 平台将该 MCP 的 `source_ref` 加入 `disabled_sources` 下发给客户端 | 客户端同步后**自动关闭**匹配该来源的已装 MCP；但保留用户填写的环境变量与密钥配置 | **停用动作无需用户确认（远程强制关闭）**；即使平台后续解除停用，也需用户自行决定是否重新开启 |
| **4. 删除平台技能制品（`DELETE /releases/:id`）** | 仅标记删除平台对象存储上的对应版本文件（且被草稿、历史发布或安装记录引用的版本禁止删除） | **不会卸载**或删除用户电脑上已经下载安装的技能文件夹 | 不涉及客户端删除动作 |

**核心审核结论**：当前架构中，**唯一支持远程强制改变本机运行开关的是“公司下发 MCP 的统一停用”**；任何类别（内置连接器、内置或公司技能、MCP）均**不支持从后台远程静默删除用户电脑上的已安装文件或配置**，也**不支持不经用户确认的静默强制代码热升级**。若未来业务需要远程强制卸载或内置连接器远程熔断停用，属于新增客户端执行能力范围，需另行立项开发。

### 内置能力（连接器 / 内置技能 / 内置 MCP）随客户端发版流程

1. **明确变更性质**：区分是“仅调整后台推荐展示（改名、改简介、隐藏入口、调排序）”还是“修改内置连接器/内置技能的实际功能代码或增删内置项”。
2. **仅调整展示时**：由 Root 或连接器模块授权管理员通过 MaaS 后台（`PUT /api/apps/starpath/admin/extensions/connectors`）修改并发布，星途客户端下次同步 `/api/apps/starpath/config` 时更新界面展示，无需重新发版客户端。
3. **修改内置功能代码、新增或移除内置项时**：必须由星途客户端研发修改客户端仓库中的内置插件/技能资源与白名单基线，打包生成新版本客户端安装包（macOS / Windows / Linux）。
4. **用户升级安装包生效**：用户下载并安装新版星途客户端后，新的内置连接器或内置技能代码才会在本机生效；旧版本客户端不会因为后台改了一条目录记录就自动获得新内置代码或删除旧内置文件。

### 管理员与用户权限边界汇总

| 角色身份 | 平台 `role` 值 | 权限范围与限制 |
|---|---|---|
| **超级管理员（Root）** | `100` | 可授予或收回普通管理员的三个模块权限（`/admin/extensions/permissions/:user_id`）、配置全局连接器策略（`/admin/config`）、配置技能对象存储策略（`/admin/skill-artifacts/storage`），并拥有连接器、技能、MCP 全部模块的读写与发布权限 |
| **被授权普通管理员** | `10`（且账号启用） | 仅能操作被 Root 显式授予 `read` 或 `manage` 权限的模块（`starpath_connectors` / `starpath_skills` / `starpath_mcp`）；**不能给自己的账号或其他人赋权，不能跨模块访问，不能修改对象存储配置或全局 `/admin/config`** |
| **未获授权管理员 / 普通星途用户** | `1`（或无模块权限的 `10`） | 仅能调用客户端读取接口拉取分发给当前账号的目录、换取授权技能下载链接并上报本机回执；访问任何 `/admin/*` 接口均返回 `403` |

## 来源隔离与 MCP 更新 / 停用细则

### 四类来源严格隔离

| 来源分类 | 识别依据 | 客户端隔离保护规则 |
|---|---|---|
| **客户端安装包内置** | 内置基线 `runtime_id` / `package_name` 或内置技能目录 | 受保护身份（`protectedRuntimeIds`），不由公司目录覆盖文件或卸载 |
| **公司后台下发** | 稳定 `source_ref`（如 `company:<id>`）及本地公司扩展注册表 | 仅公司目录中相同 `source_ref` 的条目可提示更新或触发 MCP 统一停用 |
| **第三方市场安装** | 市场来源元数据 | 公司目录同步绝不改写、停用或覆盖市场安装项 |
| **用户手动添加** | 本地自建标识 | 公司目录同步绝不接管、停用或覆盖用户自建项 |

### 公司 MCP 一键更新规则

当公司发布的 MCP 目录启动参数与用户本机已安装的同 `source_ref` 配置不同时，客户端展示“可更新”，用户点击更新后：
- **自动更新的字段**：`transport`、`command`、`args`、`url`。
- **自动保留的用户本地数据**：用户已填写的环境变量（`env`）、自定义请求头（`headers`）、本地展示名称及当前启停开关状态。
- **拦截一键更新并要求重新配置的情况**：若新版本在 `required_config` 中新增了 `required: true` 的必填项且本机尚未填写，或者新旧版本在 `stdio` 与远程传输（`http`/`sse`）之间发生了类型切换，客户端不会直接静默替换，而是提示需要补充配置；用户需重新配置或从公司推荐重新添加，不会自动打开配置表单。

### 公司 MCP 统一停用执行链路

1. MCP 模块授权管理员在后台将目标 MCP 条目的 `disabled` 设为 `true`，保存草稿并发布（`POST /admin/extensions/mcp/publish`）。
2. 客户端同步 `GET /api/apps/starpath/extensions/mcp`，从响应中读取 `disabled_sources` 数组。
3. 客户端遍历本机已安装的 MCP，凡是来源匹配 `disabled_sources` 且当前处于开启状态的条目，立即将其本机开关设为关闭，并通知已打开的界面刷新状态（工作树已修复停用后界面刷新同步）。
4. 若用户在平台仍处于 `disabled: true` 期间手动在本地重新开启该 MCP，客户端在下一次目录同步时会再次将其强制关闭；当平台管理员后续将 `disabled` 改回 `false` 重新发布后，客户端解除禁用限制，但**不会自动替用户重新打开开关**，由用户按需手动开启。

## 常见错误码与排障速查表

| 阶段 / 场景 | HTTP 状态 | 错误码 `code`（或客户端错误标识） | 原因说明与排查处理方法 |
|---|---|---|---|
| **登录与认证** | `401` | `AUTH_UNAUTHORIZED` / `AUTH_TOKEN_EXPIRED` | 访问令牌缺失或过期；读取接口单飞调用 `/api/user/auth/refresh` 刷新 1 次 |
| **会话失效** | `401` | `AUTH_SESSION_REVOKED` | 刷新会话已过期、已退出、改密或重放；立即清理本地登录态与托管密钥，重新登录 |
| **会话串号保护** | `409` | `AUTH_SESSION_MISMATCH` | `X-Auth-Session` 与当前 Cookie 会话不一致；去掉该头重试 1 次刷新以对齐会话 |
| **权限不足** | `403` | `EXTENSION_PERMISSION_DENIED` | 当前管理员缺少对应模块的 `read` 或 `manage` 权限；由 Root 在权限页核对授权 |
| **非合法授权目标** | `400` | `INVALID_EXTENSION_ADMIN` | Root 尝试给非普通管理员（`role != 10`）或已禁用账号授予扩展模块权限 |
| **接口未部署** | `404` / `501` | 客户端标记 `notDeployed` | 目标服务器仅部署了基础版或手册分支，未部署 `local/full-platform` 的星途扩展路由 |
| **并发编辑冲突** | `409` | `EXTENSION_REVISION_CONFLICT` / `SKILL_STORAGE_REVISION_CONFLICT` | 提交的 `expected_revision` 与服务端最新修订号不一致；重新 GET 最新数据比对后再提交 |
| **身份映射冲突** | `409` | `EXTENSION_IDENTITY_CONFLICT` | 同一扩展 `id` 尝试修改历史已绑定的 `source_ref`；保持稳定 `id` 与 `source_ref` 一一对应 |
| **连接器只读字段** | `400` | `CONNECTOR_FIELD_READ_ONLY` / `CONNECTOR_SCOPE_DENIED` | 尝试通过 `/admin/extensions/connectors` 新增非内置连接器或修改包名/运行 ID 等只读字段 |
| **协议版本不匹配** | `409` | `SKILL_ARTIFACT_CLIENT_UPGRADE_REQUIRED` | 目录含 `hosted_artifact` 托管技能，却调用了旧版 v2 管理接口 `/admin/extensions/skills/*`；改用 `/admin/skill-artifacts/catalog*` |
| **技能版本重名** | `409` | `SKILL_VERSION_CONFLICT` | 同一 `skill_id + version` 已有确认（`ready`）的制品版本；提升新版本号后再确认，禁止覆盖已确认版本 |
| **技能制品不可用** | `400` / `403` / `404` / `409` | `SKILL_RELEASE_UNAVAILABLE` / `SKILL_DOWNLOAD_SCOPE_DENIED` / `SKILL_RELEASE_NOT_FOUND` / `SKILL_CATALOG_CHANGED` | 当前用户不在该发布版本的分发范围内、制品不存在或未处于 `ready` 状态 |
| **技能删除受阻** | `409` | `SKILL_RELEASE_REFERENCED` | 该制品版本正被草稿、历史发布目录或客户端安装回执引用，受审计保护不可删除 |
| **上传并发繁忙** | `429` | `SKILL_UPLOAD_BUSY` | 当前平台进程的两个上传/导入处理槽位均已占用；等待后再试 |
| **托管密钥异常** | `500` | `MANAGED_KEY_UNAVAILABLE` | 服务端无法创建托管令牌；重点检查数据库是否已执行 `tokens.managed` 迁移 |
| **客户端归档校验失败** | 客户端回执 | `HASH_MISMATCH` / `UNSAFE_ARCHIVE` / `IDENTITY_MISMATCH` | 下载的 ZIP 摘要不符、含路径穿越/符号链接或 `SKILL.md` 身份冲突；客户端已中止安装并保留旧版 |
| **套餐购买结果不明** | 网络超时 / 5xx | 客户端购买状态 `unknown` | 扣款请求已发出但未收到明确响应；**严禁自动重发扣款**，先刷新钱包与订阅核对平台账单 |

## 排障日志与上线前待确认事项清单

### 建议保留的安全排障字段

排查问题时建议记录：发生时间、平台 `origin`、星途客户端版本与系统架构（`os`/`arch`）、当前登录账号 `user.id`、请求方法与路径、HTTP 状态码、平台错误码 `code`（或客户端错误枚举），以及扩展链路中的 `publication_id`、`delivery_id`、`release_id`、`operation_id`。
**严禁写入日志或截图的内容**：用户密码、`access_token`、`new_api_refresh` Cookie、`MODEL_API_KEY`、对象存储 AK/SK、短期签名下载 URL（`download.url`）、用户填写的 MCP 秘密配置值。

同时注意区分三类后台记录：
- **模型调用日志**：核对 `/v1/*` 对话请求与额度扣减。
- **目录回执（`/extensions/:module/receipts`）**：仅确认客户端已拉取推荐目录或已弹出新增通知。
- **技能安装回执（`/v3/skills/installations`）**：确认客户端本机下载、校验、解压安装或失败回滚的真实结果。
