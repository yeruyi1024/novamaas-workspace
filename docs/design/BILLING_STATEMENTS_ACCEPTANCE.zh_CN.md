# 对账单第一期验收指南

更新日期：2026-09-10。适用于隔离开发/验收环境，不是生产上线验收报告。以下金额是明确构造的示例，不对应真实客户；账户、登录信息及实际数据由验收人员在本地准备，不提交到仓库。

## 1. 两个入口分别做什么

| 入口 | 数据来源 | 用途 | 是否需要开启正式记账 |
| --- | --- | --- | --- |
| 消费查询 | 已有使用日志的消费、退款记录 | 选择日期，查看 24 小时金额；点击有记录的小时查看请求明细 | 否 |
| 月度对账的历史消费参考 | 同一使用日志，按日汇总 | 解释该月份实际已有的消费；点击日期跳到小时查询 | 否 |
| 正式对账单 | 正式记账起点之后的不可变账本及小时汇总 | 月结、固化凭证、管理员下发、客户确认、下载 PDF | 是 |

充值和临时预扣不是消费。消费为正、退款从净额中扣除；“记录数”同时包含消费与退款记录。金额按系统货币配置显示，保留六位小数。未发生的小时/日期不作为零消费展示。

历史参考数据与正式账目不会自动相互转换。正式记账从管理员配置的时间开始，不允许通过倒填真实账户起点把未经核验的历史日志变成正式凭证。

## 2. 先验收历史查询

1. 用现有管理员登录 `http://localhost:5173/billing`。
2. 搜索并选择具有已知历史消费的隔离测试客户。账户默认是当前登录人，必须主动切换，并核对客户用户名与 ID。
3. 在“消费查询”中选择有已知记录的日期。核对消费/退款数量，点击有记录的小时，检查时间、模型、消费/退款、净额和请求 ID。
4. 切换“对账单”，选择包含这些记录的月份。历史参考表应有数据，日汇总应与原始整数额度及系统货币配置一致，不能把查询失败或未发生日期显示为零消费。
5. 对正式账本为空、且正式覆盖区间内有消费日志的账户，应显示“历史账目未核验”的阻断说明，而不是正式零金额月单。尚未关闭的月份不能提前出具整月正式单。查询操作不会创建账本、改变额度或设置起点。

查询时间口径为 Asia/Shanghai；日查询默认当天，月预览默认上月。历史消费统计可能缓存 15 秒，页面显示查询数据时间和最新记录时间；当天页面每 30 秒刷新一次。查询失败会显示错误，不用零金额替代。

草稿详情中的“对账客户”应指向被选中的客户；审计记录中的“操作人”应指向执行创建、下发等动作的账户，两者不能混用。

如需给历史月份出单：月度预览打开“核验并导入历史账目”只读查看 → 如有旧空草稿，亲自填写原因并作废 → 选择 OSS 存储并刷新核验 → 对照消费/退款及充值依据 → 填写核验依据、勾选授权并二次确认导入 → 核对有数据的正式预览 → 创建新版本草稿、下载新版 PDF、下发客户。导入不自动下发、不代客户确认、不改变余额；旧版本及文件永久保留。

该入口只支持正式账本为空的已关闭月份，最多每月 10,000 条。混合账目、活动草稿、未结算操作、超限或无法安全保持起点时阻断，不截断、不覆盖。本轮开发没有对真实客户执行导入或作废。详细安全边界和 MySQL 统计策略见 [历史核验与统计说明](BILLING_HISTORY_REVIEW.zh_CN.md)。

## 3. 再验收完整出单流程

由验收人员准备隔离的普通测试客户，企业抬头明确标记“模拟验收企业（非真实交易）”，税号使用测试标识。不要为模拟数据发起真实上游请求或用于生产交易。登录信息仅通过安全渠道交付，管理员使用已有账户，不额外创建管理员权限。正式账期需要完整的新记账数据，或在符合条件时经明确核验导入；不要直接改表倒填真实客户起点。

### 示例模拟账期：2026-08

| 日期与小时 | 类型 | 金额（当前 CNY 配置） |
| --- | --- | --- |
| 08-01 10:00 | 消费 | ¥7.000000 |
| 08-15 09:00 | 退款 | ¥1.750000 |
| 08-20 15:00 | 消费 | ¥10.500000 |
| 月度合计 | 消费 / 退款 / 净额 | ¥17.500000 / ¥1.750000 / ¥15.750000 |

共 3 条记录。原始额度分别为 500000、-125000、750000；净额度 1125000。上述显示金额使用核验时的 CNY 汇率 7、每 USD 500000 额度。如系统显示配置变化，预览金额会跟随变化，已创建草稿则保持创建时的金额与币种。

1. 管理员选择准备好的隔离测试客户 → “对账单” → 对应的已关闭月份（上表示例为 `2026-08`）。
2. 选择已有启用的 OSS 归档存储。检查“出单条件检查”逐项结果：正式记账、覆盖范围、企业资料、月末后 24 小时、预扣结算、汇总数据、重复月单、存储凭据。
3. 核对“正式对账单预览”和历史参考金额，点击“创建归档草稿”。系统异步上传明细、快照、PDF 和清单，并回读校验；完成后状态从“准备中”转为“草稿”。
4. 打开草稿，核对企业主体、日期、每日金额及 PDF，管理员点击“下发”。若失败，查看错误提示，在同一张失败单中重试，不重复创建；若已存在同月单，可点“查看已有对账单”。
5. 用无痕窗口或另一个浏览器，以测试客户登录同一地址。“对账单”中只能看到管理员已下发给该客户的单据；未下发草稿对客户不可见。
6. 客户打开单据，勾选核对确认项，再提交确认。管理员不能替客户确认；系统保存客户身份、真实登录会话、确认时间戳、原件及清单摘要。确认不会重复扣费。
7. 下载原始 PDF 和确认回执。原始文件不会因确认而改变，确认回执展示确认时间与原件关联信息；管理员刷新列表后应看到“已确认”和时间。

可使用两个不同的模拟账期，分别完成自动联调与人工验收，避免自动创建的活动单据占用人工操作路径。本文不提供修改真实数据的导入脚本。

## 4. 真实客户如何开始使用

管理员在“对账资料”中维护企业抬头、税号并开启正式记账。未填写指定时间时从本次保存时间开始；填写时间只能是允许范围内的未来时间，不能倒填真实历史。

新请求的正式结算及退款进入账本。首月只覆盖正式起点之后的账目，起点前的日期显示不在记账范围。账期结束再等待 24 小时后可创建草稿；例如 2026 年 9 月最早在 **2026-10-02 00:00（Asia/Shanghai）** 创建正式月单，而不是在 9 月尚未结束时出单。

未开启、账期不覆盖、没有正式账目、汇总异常、未结束账期以及接口失败会分别提示。云端凭据能读取不等于远程读写一定成功，实际访问、金额一致性及文件摘要在归档阶段再次验证。

## 5. 实现与验收边界

- 历史查询复用已有 `(user_id, created_at, id)` 索引，限制单用户最长 31 天；按小时聚合，15 秒有界缓存及相同查询合并，数据库查询超时 5 秒。小时明细固定 100 条、游标分页，不读请求体、IP、令牌名称或管理员信息。
- 正式查询仍使用独立账本与小时汇总。创建草稿只执行一次客户/月范围的正式明细序号边界查询，避免以可能缺失的汇总作为凭证取数边界。归档再独立校验所有明细与日/月汇总；异常时禁止发布 PDF/清单。
- 归档完成状态与摘要、租约释放原子写回，过期工作进程不能覆盖新结果。摘要字段通过 GORM 模型映射，兼容现有表，无需为本次写回修复重命名列。
- 正式归档使用永久对象用途，不套用临时媒体清理规则。未修改现有云端生命周期策略，没有清理历史日志、真实账目或云端凭证。
- 测试数据库中的模拟客户/日志/账本需与业务报表区分；不要把本次试验库及测试账户当作生产上线库。测试归档是证据型永久对象，本工具不提供清理或覆盖旧证据的操作。
- 已有本地测试不等于生产容量证明。百万请求/日、热点账户、主从切换、故障注入、长期日志归档、PostgreSQL 实库验证仍需独立专项测试；本次没有引入新中间件、分区或全库调参。
