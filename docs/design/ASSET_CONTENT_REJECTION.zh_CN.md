# 素材上游审核拒绝与重传

后台同步将上游错误分为两类：网络、鉴权、限流、5xx、未知处理失败继续按现有退避机制重试；明确的真人或敏感内容拒绝，以及上游最终 `rejected` 状态，进入终态。分类基于上游结构化错误的状态码、错误码和消息，以及素材轮询结果，不用任意网络异常文本判断。错误码/文案规则需随真实渠道样本维护；不把未经确认的失败统一当作违规。

新上传素材先处于 `processing`，首次确认上游 `Active` 后才进入 `ready`。上游的 `Active` 不是永久终态：前 48 小时每 30 分钟复核一次，之后每天对账一次，以覆盖数小时后发生的复审改判。复核领取任务时副本继续保持 `active`，仅写入租约，避免正常视频请求在轮询窗口误判成“正在同步”；复核遇到网络或 5xx 时保留可用状态并在 5 分钟后重试，不把暂时查询失败改成素材失败。

终态转换在同一数据库事务中更新素材与触发拒绝的副本：素材 `status=unavailable`，写入稳定的 `unavailable_reason`（`real_person`、`sensitive_content`、`policy_rejected`）；副本 `status=rejected`，清除租约和下次同步时间，停止自动重试。同一事务按订阅端点写入不可变的 `asset.failed` 投递记录，保证不会出现数据库已改判但通知事件丢失的窗口。后续已排队的其他副本在读取到不可用素材后停止同步，删除流程仍可清理上游副本。管理员同步任务列表保留安全的原因代码和请求日志入口，不展示未经脱敏的上游原文给普通用户。

页面显示不可用状态和可理解的原因，禁止复制失效的素材引用，提供“重新上传修改后的文件”入口。重传沿用现有上传 API，创建**新的素材 ID**并重新排队渠道同步；旧素材保留不可用状态，以免旧视频请求静默使用不同文件。AK/SK 用户也可再次调用 `CreateAsset` 上传修订版；`GetAsset`/`ListAssets` 的响应以 `Status=Failed`、`FailureReason` 表示旧素材被拒绝，状态筛选与分页在数据库层完成。

视频请求进行 `asset://` 映射时，在检查渠道副本前先校验素材全局状态；不可用时返回 HTTP 422、稳定错误码 `asset_unavailable` 和重传建议。此错误属于本地请求错误，不转发上游、不重试其他渠道，预扣费走已有失败退款路径。普通“正在同步”和可重试失败仍使用原有 409 语义。

Webhook 投递使用独立后台循环，不阻塞素材状态轮询。每条事件在发送前单独领取一分钟租约，单次 HTTP 请求超时十秒，不提前领取整批任务。事件包含稳定的 `evt_...` ID，单个端点的投递使用稳定的 `wh_...` ID；失败重试复用原始请求体和投递 ID，指数退避最多 72 小时。端点查询的临时数据库异常继续重试，确认端点不存在或被禁用才停止投递。平台通过 HTTPS 直接投递 JSON，不生成 Webhook 签名密钥，客户接收端无需验签；客户如需核实状态，可使用原有 AK/SK 调用 `GetAsset` 查询。

多节点共用数据库时，投递通过条件更新领取，只有更新成功的节点可以执行任务。发送前再次核对数据库中的租约归属；数据库查询和 HTTP 请求共用原租约的截止时间，并预留五秒安全余量，暂停后恢复的旧节点不会重新获得一段发送时间。完成、失败重试和丢弃旧事件也必须持有未过期租约，不能覆盖接管节点的结果。该机制复用已有租约字段，不新增数据库结构或 Redis 锁。Webhook 仍是至少一次投递：接收端已处理但响应丢失，或发送成功后数据库写回失败，都会导致合法重试；客户仍须按 `webhook-id` 去重，不能承诺严格只收到一次。

投递记录由主节点每小时清理一次：成功和被新状态取代的记录保留 30 天，超过重试期限的最终失败记录保留 90 天。每种保留策略每轮最多删除 10 批、每批 500 条，并按状态与创建时间索引查找；待发送、投递中、可重试记录不参与清理。清理失败留待下一轮，不影响状态同步或投递。轮询任务每 10 秒领取到期工作，但已可用素材前 48 小时每 30 分钟复核一次，此后每 24 小时复核一次；这些是正常情况下的计划间隔，实际发现改判仍受上游响应与队列积压影响。上线前应按目标数据库和素材规模压测。

素材改判失败时，同一事务会把 pending/failed 状态的旧 `asset.active` 标记为已取代；投递前还会按素材当前状态检查一次。已发出的 HTTP 请求无法撤回，跨实例投递也不保证顺序，因此事件包含 `data.state_version`：可用为 1，终态失败为 2。下游按素材 ID 原子保存更高版本的状态，使用 `webhook-id` 去重；历史无版本事件通过查询接口对账。同一 ID 失败后不会恢复，重传创建新 ID。激活和拒绝事务统一先锁素材、再锁副本，与删除流程保持一致。
