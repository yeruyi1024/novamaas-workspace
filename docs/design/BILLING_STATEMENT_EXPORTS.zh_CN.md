# 月度对账单 PDF / Excel 与版本作废

2026-10-08，NovaMaaS 下游账单导出扩展。平台仍保留 new-api 项目及 QuantumNous 归属。

## 数据边界

正式对账单取不可变 `BillingEntry`，以原账单的用户、时间范围、序号范围汇总，并与冻结的逐日、模型和月度金额相互核对。临时预扣、充值和其他资金变动不作为消费；退款单独列示。金额按原始整数额度转换，保留六位小数。

附件示例包含「总览」「每日汇总」「模型汇总」。新 Excel 沿用这三个工作表的组织方式，仅列示平台能够核验的正式账本字段；缺失值不伪装成零。

| 附件字段 | 正式账单支持情况 | 新导出处理 |
| --- | --- | --- |
| 用户、企业抬头、税号、账期 | 已有冻结信息 | 总览与 PDF 列示 |
| 日期、模型名称 | 正式明细已记录 | 每日汇总、模型汇总 |
| 使用天数 | 可从模型入账日期去重 | 标为「使用账单天数」，退款日期也计入，不等同于调用天数 |
| 成功请求 | 正式明细可能包括多次结算、退款与历史补录，不等同于请求数 | 替换为消费笔数、退款笔数、正式账本记录数 |
| 实际账单 | 可核验 | 每日、模型汇总按「预扣金额、实际消费金额、退款金额」顺序列示，实际消费金额为预扣金额减退款金额 |
| 模型数 | 可核验月度模型集合 | 总览列示本期模型数量；不添加未冻结的每日模型数量 |
| 实际账单占比 | 可核验 | 模型消费金额占本期消费总额；零消费合计为 0% |
| 输入、输出、缓存写入、缓存读取、总令牌 | 部分消费日志保存相关数据，但正式账本未完整冻结，日志还可关闭或清理 | 不进入正式导出 |
| 标准原价、优惠金额、有效折扣、标准原价占比、平均折扣 | 正式账本没有完整历史原价快照 | 不导出原价列；不计算优惠与原价相关指标 |
| 分组倍率分布 | 正式账本没有保存完整历史分组/倍率 | 从历史消费日志或任务提交快照读取实际计费组、费率，按模型＋组＋费率分行列示 |

消费日志保存 `model_ratio`、`model_price`、`group_ratio`、`user_group_ratio` 等历史定价参数。成本核算的新版 `cost_basis_quota` 在配置渠道成本折扣时保存分组倍率前的金额；未配置时仍是实际成交额度。它们并非正式账本中完整、无取整误差的标准原价契约，本次按产品要求删除 PDF 和 Excel 的原价列。

## 历史实际费率

模板 10 在生成快照前按正式明细逐笔关联历史来源：历史补录优先使用 `SourceLogID`；普通消费使用用户、请求 ID、模型、消费/退款类型与额度严格匹配；异步任务调整使用持久化任务 ID 对应提交时的计费上下文。只使用当时选定的实际组与最终费率，不查询当前 Token 配置、可用计费组或当前费率。关联不唯一或历史数据缺失时保留原金额，费率标为「未记录」。ClickHouse 日志使用请求 ID，不使用不可靠的显示序号。

模型汇总按「模型名称＋实际计费组＋历史费率」拆行。相同组费率在账期内变化也拆行；同一计费标准下不同 Key 合并。费率以百分比显示，合法零倍率为 `0.00%`。消费、退款、笔数、账单日与首末入账时间均按拆分后的明细汇总；模型数量按不同模型名称统计，拆行不增加模型数量。所有行合计仍须与正式账本、每日汇总一致。

已归档版本保留冻结的历史费率和拆分行，日志被清理或 Key 被修改也不会改变。新草稿读取最新正式账务、品牌与模板，并建立独立归档；原文件保留。模板 10 及以前的渲染保持原样，以确保旧归档重试和确认回执的兼容性。PDF 与 Excel 共用历史费率拆分行，均不显示原价列或当前参考费率。模板 12 在 PDF 对账说明及 Excel 首页说明区明确消费金额、退款金额、净消费金额已包含计费折扣；旧模板的归档与回执保持原样。新模板 11 的 PDF 模型列只显示模型名称，长名称自动换行；实际计费组保留在 Excel 中，PDF 的历史费率和拆分金额保持不变。

模板 14 统一 PDF 和 Excel 全部金额为无货币符号的会计格式：金额靠右、小数位对齐，使用千位分隔、六位小数、负数括号与零值短横线。币种仅在资料区用 CNY 等代码注明。覆盖 PDF 首页三项总额、逐日/模型明细及合计、模型页净额摘要、确认回执；Excel 覆盖三个工作表及首页舍入差额。数值单元格保留原值和计算能力，超过 Excel 15 位有效数字的金额以精确文本保存并采用相同金额显示。模板 13 及以前仍按原样生成，既有文件摘要不变；新格式通过作废当前版本后创建新草稿取得。

模板 18（2026-10-09）保留 PDF 原有蓝灰、深蓝、白字和确认信息的绿色配色，以及表头和实际消费金额卡片的深蓝底色。逐日消费明细与模型消费明细的客户名称直接显示冻结的企业名称，不加「抬头」前缀；逐日明细的客户名称、版本与时区行，以及首页服务平台、账期、客户资料和明细记录说明，使用下方说明文字相同的蓝灰色。账户余额按原始精度累计后使用两位小数会计格式，负数以括号显示并保留千位分隔；每日余额、上期余额与合计余额均与其他金额对齐。Excel 总览不再列示「账单数据 SHA-256」；每日汇总、模型汇总将「消费金额」改为「预扣金额」，将「本期净额」改为「实际消费金额」并置于退款金额之前，明细与合计金额同时调整列序。金额计算、精度及内部归档摘要校验不变；模板 17 及以前保持原样，新建草稿使用模板 18。

## 费率误配置的补救边界

费率误配置通过「对账 → 调账」独立处理。仅超级管理员的真实登录会话可创建预览；执行和撤销还需 `billing.correct` 范围的二次验证（认证器或 Passkey），并明确确认客户编号和净差额。普通管理员、客户和个人访问令牌不能执行。

当前支持已终结、钱包扣费、按固定单价计费且提交参数可核验的异步任务，覆盖 Wan Prime 视频场景。选择客户、北京时间日期范围、模型和目标计费组；目标费率由系统当前组配置与该客户所属用户组的覆盖配置确定。保留提交时模型单价、时长等倍率，只替换分组费率，不按今天的模型单价重新计费。原费用已折扣并取整，不能直接除旧折扣再乘新折扣：必须重放历史的基础费用取整和附加倍率取整两步，并逐笔准确复现原费用；`PerCallBilling` 只控制轮询差额结算，不代表提交费用忽略时长倍率。无法复现时整个批次禁止执行。

每批最多 20 个模型、93 天、1000 条正式账项，必须完整涵盖消费与退款生命周期。全额退款任务的消费、退款一起重算，净差额抵消，不补扣；部分退款、动态表达式、订阅、未终结任务及证据缺失暂不支持。任一条不满足条件即拦截整批，预览仍展示原因。正式记账起点之前的账项不纳入调账。日期与序号同时遵守正式账本边界：仅选择 `StartSequence ≤ sequence ≤ 预览时 Sequence` 的有效账项，历史补录前的旧账项不会再次计算。同一消费不能把旧账项与补录账项叠加成两笔扣费。

渠道变化和模型计费变化调账均可在非出账日处理当月账目，界面默认本月 1 日至今天。日期按北京时间解释；结束日为今天时，服务端将范围终点截断并冻结为创建预览的时刻，后续消费不进入该批次。未来其他时刻仍拒绝，未完成任务及完整消费/退款生命周期检查沿用原规则。

预览只保存纠错定义、逐笔差额和 SHA-256，不扣款。预览有效 15 分钟，执行前重新核对原账项、任务计费快照、客户所属组、目标费率、预览摘要和账本序号。存在未结算预扣、重叠已调账记录、钱包或有限额度 Key 余额不足时整批失败。钱包、用户/Key/渠道累计用量、新账项和收入差额快照在一个事务中更新，重复请求不会重复扣款。

原日志、任务计费上下文、原账项和原渠道成本快照保留；执行时新增 `rate_correction` 账项，关联原账项、批次和操作者。收入随差额变化，此操作没有新上游请求，新增上游成本为零。管理员使用日志逐笔新增「调账」类型记录，包含原因、批次、来源编号和有符号差额；客户日志、客户日志统计及 Key 日志接口均排除此类型。日志数据库故障时通过持久化待办重试写审计，不重扣钱包。

整批撤销要求原操作人再次验证并填写原因，新增相反账项恢复余额和计数，不删除既有审计。已确认旧版账单保持原样。新账单按原消费/退款所属月份合并调账差额，钱包账项及管理员审计仍保留实际操作时间；不会把同一差额再计入操作月份。账单需要更新时，先作废有效版本，再按最新账务生成新草稿；作废和出单不重新扣款。可下载纠错 JSON 明细供管理员验证。此工具不会修改模型今后的路由/分组配置，错误配置仍须单独修正。

## 品牌与文件名

对账 PDF 有独立的多页模板，使用与其他 PDF 一致的品牌配置和运营标识安全读取/归一化逻辑。旧模板 7/8 的页眉漏掉了运营标识分支，新模板 9 修复右上角运营标识，并保留旧模板用于已有归档的原样重试。

PDF 和 Excel 的下载名优先使用冻结的企业抬头，未填写时使用冻结用户名，再回退到用户编号：`企业抬头_YYYY-MM_月度对账单_VNN.pdf` / `.xlsx`。保留版本号以区分历史版本；路径分隔符与控制字符会清理。确认回执同样优先使用企业抬头。

## 双文件归档与校验

1. 核对原范围的正式账本、逐日汇总、模型汇总和月度合计。
2. 按冻结快照生成 Excel，永久存入同一 OSS 归档资料源，读取校验后获得 SHA-256。
3. 在 PDF 封面写入 Excel SHA-256 和账单快照 SHA-256，再归档 PDF。
4. 校验清单版本 2 同时保存 PDF、Excel、账单快照以及明细分块摘要。客户确认清单摘要，即绑定两个文件；确认事件和回执也列示 Excel 摘要。

Excel 中记录账单编号和版本；模板 17 及以前还列示快照摘要，模板 18 起隐藏该展示行，内部快照校验及清单摘要继续保留。不反向写入 PDF 摘要，以避免两个文件相互引用造成循环摘要。金额超过 Excel 15 位有效数字时以原始六位小数字符串保存，避免精度损失；模型名等外部文本不作为公式执行。工作簿 ZIP 顺序和文档时间固定，归档重试生成相同字节。

新模板必须成功归档 PDF、Excel 与校验清单后才能成为可下发草稿。旧模板的归档和确认保持原有规则，不强制补写 Excel。下载继续执行账号权限及 OSS 摘要校验，不提供公开文件链接。小程序使用原鉴权下载接口，并在打开 PDF/Excel 时明确文档类型。

## 作废后创建新版本

同一客户、同一月份最多一份有效账单。有效账单包含准备中、失败、草稿、已下发、争议中和已确认版本；作废版本及旧功能产生的已被替代版本不占用有效名额。创建、出单检查、历史导入检查统一使用该口径，并在账户锁内复查；版本号从该客户该月全部历史版本的最大编号递增，不只检查最新一行。

移除「重新生成」和「按调账更新账单」入口及后端操作。账务、品牌或版式发生变化时，管理员填写原因作废当前账单，再按最新数据创建新草稿。已确认账单也允许管理员作废，保留原企业信息、金额、快照、文件摘要、下发/确认时间和客户确认事件；原 PDF、Excel、校验清单及确认回执仍可下载。作废新增审计事件、释放有效版本名额，不改变钱包余额或历史账项。新版不继承原确认，须重新归档、下发和客户确认。已被替代旧版展示「已被替代」且不可继续操作，避免把残留草稿误认为有效版本。

历史导入凭证与原账项永久保留，无需废弃或重复导入。调账账项通过 `source_entry_id` 关联原消费/退款；新正式账单采用 `accounting_basis=source_period_corrections_v1`，消费与退款分别按原记录金额加已入账差额得到更正金额，所属日/月仍为原记录日期。模型汇总采用最后一笔关联更正的计费组与费率，笔数仍是原消费/退款笔数；跨月批次按每条原记录日期分别归属。操作月份排除这些调账账项，避免重复出单。原日志、账项和钱包入账时间不改，出单不再次扣款。

新草稿冻结创建时最新账本序号上界，并使用当前账务资料、币种配置、品牌与模板。归档明细保留原记录日期、来源摘要、原配额和关联更正的序号、实际入账日期、差额及批次编号；快照、明细分片、PDF、Excel 和校验清单以摘要绑定。清单 schema 3 明确归属口径。归档重试仅读取冻结序号以内的更正，因此后续撤销或新调账不会改变旧版。撤销新增相反账项，作废后创建的新版本可恢复原金额/费率。新原月份账单若遇到另一有效旧账单已按操作月份收录同一差额，必须先作废该操作月份账单，再按新口径生成；不能同时让两份有效账单包含同一差额。

尚未包含最新更正的未确认账单会显示先作废再创建草稿的提示，并阻止下发/确认。检查在账户锁内再次执行，与调账提交保持相同锁顺序。消费查询使用原日志口径保持原样；正式对账预览与新账单使用更正后的账务口径。

## 详细日志工作表与日志导出

新建草稿（快照 `detail_sheet=true`）的 Excel 增加「详细日志」工作表，一个请求（视频任务按任务）一行；旧快照不带该标记，工作簿与原来逐字节一致。超过单表行数时续写「详细日志2」等。

金额列按账本口径拆开：`首次扣费 + 补扣金额 − 退款金额 = 实际扣费金额`。请求合并后对各金额分量保留六位小数；整月总览仍由整数额度汇总后换算。两种舍入顺序产生差额时，在总览分别列示「详细日志消费/退款/净额舍入差额」，对应明细列合计加差额等于总览金额，不调整账本或客户扣费。视频任务按发生时间确定首次预扣，其后的补扣、退款并入同一行，历史导入的追加序号不改变该顺序；旧视频日志没有任务号时，按同一用户任务提交时间前后 1 秒内唯一的任务关联，有两个候选则不猜。文本模型有真实预扣记录时，另列「预冻结金额」，它是调用前的临时冻结，不计入消费，不进任何合计；未预扣的说明写「未预扣」。没有数据的可选列不显示，零显示短横线，不展示平台成本、利润、渠道或供应商信息。

详细日志的令牌名称、用量和关联信息在首次生成 Excel 时补充。已有 Excel 归档的重试会先读取并校验原文件，再复用其摘要；之后令牌改名或日志补写不会重新生成该文件。读取失败或摘要不符时明确失败，不覆盖原件。

使用日志页的「导出」生成供查询与核对的 Excel，列与正式对账单详细日志不要求一一相同：只含消费和退款（不含充值、管理、系统、错误、登录、账务更正），金额币种跟随系统显示币种，时间按东八区墙上时间，导出前弹窗逐项列出已选条件。单次最多 366 天、20 万条，同一节点同时最多 2 个导出，导出文件在内存中完整生成后才返回，失败不留半个文件。日志导出按日志记录金额统计，不证明钱包已完成结算；汇总页明确说明正式对账金额以已归档对账单为准。结算失败时消费日志仍可能存在，此类记录不在正式账本，不能通过只补账本来证明已经收款。正式记账起点前的历史消费、未入账消费，以及已入账费率更正，也可能使日志与正式账单金额不同；核对时需统一范围、筛选条件和币种换算依据，逐项解释差额。

日志导出的首张工作表「汇总」列示本次筛选时间、币种、消费金额、退款金额、净消费金额，以及原始日志条数和任务合并后的明细行数；第二张「使用日志」保留完整明细。合计直接累加本次导出的原始日志额度，再换算显示币种，不重复计算已合并的补扣和退款，也不把明细行数当作请求数。只筛选消费或退款时，汇总也只统计该筛选结果。

「汇总」下方按模型列示消费、退款和净消费金额，按净消费从高到低排列，同额按模型名排列；模型名保留大小写区别，缺失时显示「未标注模型」。逐模型舍入与总额的差异单独列为「舍入差额」，三列合计与上方总额一致。
